### Building a Global Islamic Knowledge Platform Through Collaboration, Research & Technology

**Assalamu Alaikum (Peace be upon you)!** 🌍

# 🕊️ 1. Our Core Philosophy

Before contributing, every participant should understand the principles that guide this project.

### 1.1 Unity Without Erasing Scholarly Differences

Our focus is Fiqh-e-Muqaran (Comparative Islamic Jurisprudence).

We aim to document different recognized scholarly positions fairly and respectfully rather than promote sectarian hostility.

We do not require contributors to abandon their scholarly traditions. We require them to represent other traditions accurately.

### 1.2 Evidence and Source Integrity

Islamic research must be supported by traceable evidence.

Contributors should provide:

- Quranic references where relevant.
- Hadith references where relevant.
- Original scholarly book references.
- Author and compiler information.
- Volume and page numbers where available.
- Edition and publication details.
- Scholarly attribution.
- Translation attribution.

A religious claim must not be presented as an established fact merely because someone has published it.

### 1.3 Respectful Academic Environment

We maintain a respectful, professional and research-oriented environment.

- No sectarian harassment.
- No personal attacks.
- No fabricated references.
- No deliberate misinformation.
- No plagiarism.
- No religious insults.
- No manipulation of contribution points.

### 1.4 Transparency

Every meaningful modification to Islamic content should have a traceable history.

We aim to preserve:

- Original source information.
- Contributor attribution.
- Review decisions.
- Previous versions.
- Correction history.
- Scholarly disagreements.

You can help with:

- Quran translations.
- Hadith translations.
- Website localization.
- Android application localization.
- Documentation translations.
- Islamic terminology dictionaries.
- Arabic-to-other-language translation verification.

### Translation Guidelines

1. Never modify the original Arabic Quranic text to accommodate a translation.
2. Preserve verse and Hadith identifiers.
3. Identify the original translator.
4. Include source and licensing information.
5. Avoid presenting personal interpretations as established translations.
6. Clearly distinguish translation from explanatory commentary.
7. Ensure Arabic text and Tashkeel are preserved correctly.

Translations of copyrighted publications must not be submitted without appropriate permission or licensing.

## 🔍 2.6 Islamic Research & Tehqiq

Research contributions are among the most important parts of this project.

We welcome researchers who can investigate, verify and document Islamic references.

### Research Categories

- Quranic research.
- Hadith authentication research.
- Narrator studies.
- Fiqh investigations.
- Comparative jurisprudence.
- Arabic linguistic research.
- Historical Islamic research.
- Scholarly source verification.
- Translation verification.

### Tehqiq Submission Requirements

A research submission should ideally contain:

1. Research title.
2. Research question.
3. Introduction and background.
4. Research methodology.
5. Supporting Quranic references where relevant.
6. Hadith references where relevant.
7. Original scholarly references.
8. Analysis and discussion.
9. Findings and conclusion.
10. Limitations and unresolved disagreements.

### Research Integrity

- Do not fabricate references.
- Do not remove context from quotations.
- Do not misrepresent a scholar's position.
- Distinguish personal conclusions from attributed scholarly opinions.
- Mention differences in Hadith grading where relevant.
- Identify the edition used for book references.
- Disclose uncertainty and incomplete research.

A submission does not become verified merely because it contains references. The evidence and reasoning must also be examined.

# 🛠️ 5. Development Workflow: How to Submit a Pull Request

We follow standard GitHub contribution practices.

## Step 1: Fork the Repository

Visit the original repository and click the **Fork** button.

This creates a copy under your GitHub account.

## Step 2: Clone Your Fork

Replace `YOUR_USERNAME` with your GitHub username.

```bash
git clone https://github.com/YOUR_USERNAME/islamic-encyclopedia.git

cd islamic-encyclopedia
```

## Step 3: Add the Original Repository as Upstream

```bash
git remote add upstream https://github.com/ORIGINAL_OWNER/islamic-encyclopedia.git
```

Replace `ORIGINAL_OWNER` with the original repository owner's username.

Check your remotes:

```bash
git remote -v
```

## Step 4: Synchronize Your Fork

Before starting new work:

```bash
git checkout main

git fetch upstream

git merge upstream/main

git push origin main
```

If the repository uses a different default branch, replace `main` accordingly.

## Step 5: Create a Feature Branch

Always create a separate branch.

For example:

```bash
git checkout -b feature/swahili-translation
```

Other examples:

```bash
git checkout -b feature/quran-search

git checkout -b feature/hadith-verification

git checkout -b feature/community-qa

git checkout -b fix/database-importer

git checkout -b docs/research-guidelines
```

Avoid working directly on the main branch.

## Step 6: Make Your Changes

Follow the relevant project guidelines.

Before submitting:

- Review your changes.
- Remove temporary files.
- Check for accidental data deletion.
- Run available tests.
- Validate database changes.
- Verify source references.
- Ensure no credentials or private information are included.

## Step 7: Commit Your Changes

Use descriptive commit messages.

Examples:

```bash
git add .

git commit -m "feat: add Quran search endpoint"
```

```bash
git commit -m "fix: correct Hadith chapter mapping"
```

```bash
git commit -m "docs: improve contribution guidelines"
```

Suggested commit prefixes:

| Prefix | Purpose |
|---|---|
| feat | New feature |
| fix | Bug fix |
| docs | Documentation |
| data | Dataset modification |
| research | Research contribution |
| i18n | Translation and localization |
| refactor | Code restructuring |
| test | Testing |
| chore | Maintenance |

## Step 8: Push Your Branch

```bash
git push origin feature/quran-search
```

Replace the branch name with your actual branch.

## Step 9: Open a Pull Request

1. Visit your fork on GitHub.
2. Click **Compare & pull request**.
3. Select the original repository as the base.
4. Provide a descriptive title.
5. Explain your changes.
6. Include screenshots where relevant.
7. Include references for religious data modifications.
8. Submit your Pull Request.

Maintainers may request additional changes before merging.

# 📦 6. Large Database Files & GitHub Limits

This repository may contain substantial Quran and Hadith datasets.

GitHub enforces file-size limits, so contributors must follow appropriate storage practices.

### Important Guidelines

- Avoid committing unnecessary large files.
- Do not upload temporary database exports.
- Keep generated files out of Git unless required.
- Validate database changes before submission.
- Prefer reproducible data migrations over replacing entire databases.
- Use Git LFS where appropriate.
- Consider GitHub Releases or dedicated dataset hosting for large distributions.

GitHub generally blocks regular Git files larger than 100 MB.

Keeping files below 90 MB is a useful precaution, but it does not guarantee that repository growth will remain manageable.

Compression does not bypass the Git file-size restriction if the compressed file itself exceeds the limit.

Never commit database passwords, API keys, authentication tokens or private user data.

# 🛡️ 8. Code of Conduct & Community Rules

All contributors are expected to follow these principles.

Treat every contributor respectfully, regardless of their background or scholarly tradition.
